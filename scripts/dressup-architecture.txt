花间衣橱 / architecture

VuePress page: blogs/other/flower_wardrobe.md; Vue 2 component: FlowerWardrobe.vue.
Pure state/economy: dressup/engine.mjs. All item IDs, prices, tags and quest rewards are data.
Art: fourteen original complete outfits x three separately illustrated poses. Changing garments uses
full outfit sprites, so sleeves, hair, skirt and hands maintain correct occlusion in every pose.
Fine wardrobe: separate neutral-standing model, 12 component categories and 111 selectable options.
V5 art starts from one blank-feature full-body master. Clothes, footwear, hair and socks are
generated already worn on that exact model, then extracted on a shared 512x1024 canvas.
No runtime alpha-bound fitting, product-shoe scaling or flat-color eyebrow cover patches.
Natural-waist anchors are registered in the build pipeline; head/feet anchors remain fixed.
The master suppresses its covered torso/hips, while retaining original arms and exposed legs.
Shoes preserve their actual worn position; transparent instep windows reveal chosen socks.
V7 head: one genuinely feature-free head with a single shared nose; jaw/cheek silhouettes
are morphed independently without moving central feature landmarks. Eyes, brows and lips
are isolated registered pigment, not skin rectangles from different complete heads.
Hair uses imagegen hair-only extractions with no geometric ear holes, except hair-2:
the ponytail wearable is restored byte-identically from v6/hair-2.webp and pinned by regression.
Its independent v7/catalog/hair-2.webp design card cannot change that registered wearable.
V8 jaw interpolation uses small smooth cheek profiles (face-fit.mjs), fixes the nose,
and leaves every neck pixel below y=148 unchanged. No abrupt local jaw/neck widening.
Ear jewellery draws after front hair at fixed anatomical lobe anchors, verified for each hairstyle.
Solid hats cover ponytail roots via their measured top silhouettes (hat-coverage.mjs),
not a horizontal y=59 crop that erases the side hair. Hats originate worn on a cropped head reference,
then the fixed inverse crop transform puts them onto the shared full-body canvas.
Product/design cards use a separate v7/catalog path with a single warm-ivory background.
Six new patterns (v10) add 6 tops and 6 skirts, each in one colour: crystal
princess, butterfly petals, strawberry tea party, cable-knit academy, forest
wrap and jade lotus. Existing originals and material editions are unchanged.
Product boards are independently generated illustrations, not worn-model crops.
New skirts use only exposed legs below y=490 in their neutral underbody; near-white chiffon must
never be treated as exposed legs. New cuts are tested against all original cuts.
Two replacement brows use natural hair pigment only, fitted to the actual brow
landmarks; non-pigment forehead/hair/eye pixels are compared byte-for-byte for
every face/hair pair. Sources, prompts and landmarks: wardrobe-v10-art.json.
V11 adds two new designs each for hair, headpieces, hats, earrings, socks and shoes.
Independent product illustrations remain separate from registered wearing sprites.
The new skirts cover the complete master waist/hip silhouette on both sides;
v11 replaces only their wearables, leaving their v10 product designs unchanged.
Crown and straw-hat forehead matte islands are removed without touching hair/face.
Rose-gold crown dye includes silver-metal midtones, retaining pearl highlights.
Stockings and boots follow master calf/ankle/foot landmarks; shoe opening heights
clip stockings without obscuring them inside ballerina instep windows.
Sources, prompts and attachment landmarks: scripts/wardrobe-v11-art.json.
Actual model matrices: 72 hat/hair, 48 crown/face/hair, 24 jewellery/hair,
54 shoe/sock and 108 top/new-skirt combinations in test-dressup-accessories.mjs;
168 cap/face/hair checks also compare unoccluded side hair pixel-for-pixel.

32 material editions (8 tops, 8 bottoms, 6 headpieces, 6 hats, 4 earrings)
reuse existing registered sprites and independent catalogue art. collections.mjs
declares colour/print and sourceIndex; materials.mjs preserves alpha and anatomy,
uses no Safari canvas filter API, and keeps only 4 derived canvases (about 8 MB
for full-body layers). Editions download no extra garment/hat bitmaps.
V9 crescent/angled eyebrows use distinctly different native vector contours at
the same registered brow landmarks, with transparent hair pigment only.
Build native brow art: SHARP_PATH=<sharp> node scripts/prepare-wardrobe-brows.mjs.
Edition fit/catalogue and browser composition checks: scripts/test-dressup-editions.mjs.
Clothing/accessories use standalone product art; beauty/hair/hat/sock cards use independent
imagegen design atlases (scripts/wardrobe-v7-art.json), never worn-layer crops.
Four eye choices and eight sock options include ankle, mid-calf, knee and thigh-high lengths.
Fine mode uses standing pose and optional face zoom; all clothing choices persist across zoom.
Original whole-body sources and prompts: scripts/fixtures/wardrobe-v5-sources and wardrobe-v5-art.json.
Rebuild extraction: SHARP_PATH=<sharp> node scripts/prepare-wardrobe-v5.mjs.
Head/catalogue rebuild: SHARP_PATH=<sharp> node scripts/prepare-wardrobe-v6.mjs.
V6 built-in imagegen sources/prompts: scripts/fixtures/wardrobe-v6-sources and wardrobe-v6-art.json.
Seven scenic raster backgrounds are shared by stage, scene cards and photo export.

Economy: starting 100, daily40, 12 once-only invitations, repeatable five-color workshop25.
Purchases validate balance, known ID, ownership. All mutations synchronous. Read latest save
before mutations; storage event syncs other tabs. No network economy, paid currency or leaderboard.
LocalStorage version1 normalizer filters unknown IDs, invalid balances and locked look references.
This is deliberately client-local casual progression, NOT a tamperproof server economy.

Loading: stable canvas retains previous model until the latest requested image is decoded.
Sequence tokens ignore late responses; decoded-image cache is bounded to 24 entries.
Fine mode decodes every requested layer before drawing one complete offscreen frame atomically.
Resize and context restoration repaint the last ready image without resetting canvas dimensions.
Errors expose retry. Only the selected pose is loaded at full size; wardrobe thumbnails lazy load.
Photo export: same-origin WebP decoded into canvas, Blob preview + download + iOS long press.
Maximum 12 saved look descriptors, no image blobs in localStorage.
v1 saves gain ownedParts/look.mode/look.parts defaults without losing old balances or purchases.
Album snapshots clone nested component selections; photo export snapshots the actual visible bitmap.
Memory, themed styling and sewing games use pure state transitions; completion emits one reward.
Recent game session IDs persist to prevent duplicate reward processing.
Fitting-room drafts are independent per category, not a single preview ID. Owned choices only replace
their own slot; buying one preview retains the other slots. Drafts never grant ownership or enter saves.
Face zoom only changes CSS framing, never the look state or draft.

Audio: dressup/audio.mjs starts licensed Dream Culture music after user interaction.
Music and synthesized action cues have independent persisted switches; backgrounding pauses audio.
Attribution: public/audio/dressup/CREDITS.md and the game introduction.

SSR: no DOM/storage/image APIs at module load. Vue mounted initializes browser state and events.
Destroy removes listeners/timers, invalidates loaders, restores body scroll and revokes Blob URLs.
Portrait: stage above controls. Landscape: stage left, controls right. CSS fixed fullscreen supports
Safari without native fullscreen. Dialogs use focus return, focus trap and Escape; no system alerts.
