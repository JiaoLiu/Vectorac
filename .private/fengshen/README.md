## 正常开局流程（第三轮）

开始身份局 → 随机分配 1 主公、1 忠臣、2 反贼、1 内奸 → 显示自己的身份，其他人只公开主公 → 主公先选将并亮出 → 给其他人分配各自候选 → 其他人确认后统一亮将 → 系统自动发四张初始手牌 → 主公开始第一回合。

准备大厅没有自由选将或自选身份。人物图鉴只用于查阅，不能从图鉴直接带角色入局。显示身份后会自动进入选将，也可以点击按钮跳过等待；选将完成会自动发牌，不要求玩家再点击启动。

当前 9 名角色技能可用：主公的候选为姬发、帝辛、云中子三名主公型角色，加两名随机角色，共 5 选 1。主公选定后，未选候选退回将池；其余 8 名角色打乱后，每个非主公获得独立的 2 张候选。已选主公不会再次分配，四个候选包互不重复。将池扩至足够数量后，新开局自动增加到每人 3 张；这是小将池内测适配，不把 2 张说成经典标准固定数量。

身份、发到手中的候选和已确认选择在选将时立即存档；刷新不会重新抽签。旧版已经开始的牌局仍能继续。所有角色确认后，将已分配身份和已选角色直接交给战斗引擎，不会再次随机分配。主公仍获得一点体力上限，并且第一个行动；摸牌、语音和技能按已经选定的人物执行。

实现：`setup.mjs` 为开局状态机，`setup-ui.mjs` / `setup.css` 为准备界面；战斗仍使用同一个引擎。AI 只接收自己候选、自己身份和公开的主公角色，不读取其他人的身份或候选。`createGame()` 保留为旧 API 与测试夹具入口，正常界面改用开局状态机和 `createAssignedGame()`。

参考：[三国杀官方身份模式说明](https://www.sanguosha.com/mode)、[正版运营站身份规则](https://game.qidian.com/Game/showNews/index?name=sgs&nid=1082111)。主公先选、其他人从分发的候选选将按本轮明确的经典身份流程实现。

## 设计与实现

### 第九轮手机牌桌

横屏把出牌按钮放在手牌右侧，不再在底部层层堆叠；667×375 的手牌从54px宽放大到70px，844×390从60px放大到76px。头像、技能、装备在限定区域内排布；手牌至少露出约85%卡宽，多牌横向滑动，选中抽起。标题采用墨字/楷体、纸底和小印章，仍沿用独立原创插画，所有封神牌名保持单行。

攻击和目标预选由人物之间的黄色箭线表达，群体攻击连至所有存活目标，不再在中央显示“谁→杀→谁”。迷魂阵/天雷劫在头像顶角有牢笼/雷电标记；公开判定翻牌后在牌上盖 ✓（效果生效）或 ×（效果未生效），不是把危险判定的“成功”说成玩家获益。

仙山采宝持续展示公共牌池与选牌者/所选牌名；仅新增已公开选牌的事件，未公开其他人的暗手牌。经典引擎默认投影和日志保持原样。正常身份开局的选将进度仍展示已亮出的角色。

第一次读取偏好时教学提示默认开；回合栏的问号按钮可关闭并保存。关闭后选牌不显示教学说明，出闪、选目标、确认/放弃等必要控制仍保留，不把教程开关变成自动出牌。规则及图鉴仍可主动打开。

追加整桌修正：背景覆盖整张牌桌，底部手牌层改为透明覆盖，不再把人物限制在一条狭窄上半区；人物围桌分布。横屏无装备头像放大至94×116，较宽的短竖屏预览放大至104×128；多装备时为装备列表保留空间。牌堆移入顶部左侧信息栏，摸牌动画从那里飞入手牌。所有安全区仍避开刘海和底部手势区域。浏览器模拟尺寸验证后必须 reset，避免把844宽视口缩放进较窄的应用面板，造成整桌看起来很小。

参考用户提供的英雄杀/三国杀手机截图的信息层级与交互；公开资料入口：[英雄杀官方资料](https://yxsm.qq.com/web201406/gamedata.shtml)、[三国杀移动界面介绍](https://www.sanguosha.com/act/mobile/index.html?t=11007)。本项目没有下载或复用其中商业人物/卡牌素材。

`theme.mjs` 为唯一主题配置；`art-prompts.mjs` 保存 20 人与 32 类卡牌的独立生成提示。使用内置 imagegen 逐资产生成，不套用三国杀或英雄杀的商业人物素材。原始生成文件保留在生成目录，项目使用 JPEG 优化版。

人物图在 `assets/heroes/`，卡牌图在 `assets/cards/`，`assets/manifest.json` 记录素材来源与尺寸。头像与点将卡片使用 320px 长边缩略图，人物大图与详情使用 1024px 长边图，避免手机列表加载所有大图。四种势力分别使用玉绿晨金、赤铜玄黑、清玉淡金、紫金夜色。中文牌名、点数、花色由代码渲染，避免图片内的小字模糊。

手机版竖屏：人物列表独立滚动；高屏对手围桌分布在上方和两侧，短竖屏改为上方四席并列，避免头像重叠。横屏采用围桌布局，个人区在手牌左侧。操作提醒独立成一条。中央区域展示出牌、响应牌、公开判定、无懈，以及顺手／过河的区域选牌。对局和响应窗口在旋转与刷新后保持。

### 第五轮：判定、托管与移动展示

- 点击开局或继续时尝试原生全屏，并调用横屏锁定；头部 `⛶` 可进入／退出。某些 iPhone Safari、WebView 会拒绝元素全屏或方向锁定，此时保留可玩的横竖屏布局，需手动旋转手机。没有用整页 CSS 强转冒充系统横屏锁定。
- 每个本人的出牌／响应窗口默认 60 秒，选牌、重选或查看图鉴不会重置计时；暂停、切后台与移牌展示时间不计入。超时进入持续 AI 托管，顶部或底部“接管”恢复本人操作。刷新回到手动模式，不把 AI 托管状态永久写进存档。
- 杀、决斗或群体攻击没有手牌响应、转化、防具判定或主公援助时，立即执行唯一合法的放弃并结算，不显示无意义的确认窗口。有转化、防具或援助时仍保留真实选择。
- 画地为牢（当前经典牌 `indulgence`，规则基准为乐不思蜀）和闪电的判定牌公开翻到中央。翻牌动效约 0.55 秒，展示约 1.8 秒，再执行跳过出牌、传雷或三点伤害。判定结果不是重抽；中途刷新继续展示同一张牌，再一次性完成结算。其他判定技能的扩展展示不冒充本轮已做完。
- 自己的头像下沿持续标出“画地为牢／闪电”；其他玩家头像有牢／雷标记。装备改为逐件竖排，包含武器、防具、进攻坐骑和防御坐骑，点装备可查完整效果。
- 卡牌重新采用上方浅底醒目牌名、下方原有插图。叠放时至少露出约 58% 卡宽，再多则允许左右滑动，不压成难点的细线。选中抽起 21px 并显示完整牌面；提供展开手牌面板。选中牌的可见区域就是它的点击区域，旋转保留选择。
- 谁出杀、谁响应闪、谁受伤分别标识；中央同时展示已用攻击／响应牌。借刀可把自己设为第二目标，仍保留持刀者攻击距离限制。
- 顺手／过河选择后有约一秒移牌动画：暗手牌移动时保持牌背，已明置装备／判定牌展示牌面；实际手牌数量和装备跟随合法结算更新。
- 原创天庭斗法背景由内置 imagegen 生成，保存为 `assets/heavenly-arena.jpg`；完整提示与来源见 `assets/environment.json`。受伤音效及 48 秒循环背景音乐由本地脚本原创合成，不使用商业游戏录音。音乐音量 15%，“乐”与“声”独立开关；首次手势后播放，后台暂停。

参考：[三国杀移动端牌桌截图](https://game.xiaomi.com/viewpoint/1359077112_1649661016211_9)、[官方借刀规则](https://guozhan.sanguosha.com/a/kapaiyilan/youxipai/jinnanpai/2013/0128/98.html)。仅借鉴信息层级和操作原则，不复制商业界面图片。

### 无中生有的摸牌展示

无中生有成功结算后，两张牌背从标明数量的牌堆依次飞入使用者的手牌区域，头像显示“摸牌 +2”，操作提示明确指出摸牌者。自己收到的新牌自动滑入可见区域并高亮；对手的牌只显示牌背，公开事件只保存实际摸牌数量，不包含牌面或手牌 ID。展示约 1.3 秒后恢复操作及 AI 行动。无懈抵消时不飞牌；牌堆确实只能摸到一张时按实际数量展示，刷新存档不会重复摸牌。集智的独立摸一张不被误计为无中生有的两张。

### 第二轮交互改进

- 自己的身份在顶部和个人头像旁持续显示，阵亡后仍可看；打开弹窗时标题区也保留自己的身份。其他人阵亡显示公开身份条，只有立绘灰化，身份文字不一起淡化。
- 摄宝／顺手牵羊与破阵／过河拆桥在中央区选择手牌、装备或判定区。对方手牌逐张显示牌背，不暴露实体 ID、花色、点数或牌名；选中的索引对应那一张实际手牌。装备和判定牌按明置牌展示。
- 破法／无懈可击在中央显示正在反制的锦囊、来源、目标和自己的可响应牌。反无懈时明确提示原效果会恢复。
- 本原型默认自动选择发动仙机／集智、仙姿／英姿、帝威／奸雄、雷袭／铁骑。它们仍按原效果结算，不需要“发动／不发动”确认；有真实代价或替代效果的剑威／裸衣、乾坤圈等仍由玩家选择。公开经典目录的默认行为没有跟着改变。
- 每种实际卡牌均有男女声：男声 `zh-CN-YunxiNeural`，女声 `zh-CN-XiaoxiaoNeural`。32 类卡牌 × 2 加 15 种技能 × 2，共 94 个 MP3，总计约 1MB。通过免费、无需 API Key 的 Edge TTS 预生成，运行时只播放本地文件，不在线合成。
- 语音以实际使用的牌为准，例如九转把闪作为杀使用时播“杀”。按出牌角色性别选声；非法动作和刷新不重复报牌。Web Audio 在用户第一次操作时解锁，AI 等待当前报牌结束再继续，避免叠音。

语音脚本：`python3 .private/fengshen/generate-voice.py`；只把卡牌和技能名称发送给 TTS，不发送密钥、存档或整个工程。`assets/audio/manifest.json` 记录生成音色和所有文件。

布局参考：[手游对局截图与身份介绍](https://game.xiaomi.com/viewpoint/1490293045_1671945360158_133)。技能基准：[官方黄月英介绍](https://www.sanguosha.com/hero/7)；集智原本允许选择，本原型按用户要求默认自动发动。语音生成工具：[Edge TTS 项目](https://github.com/rany2/edge-tts)。这些参考不是美术素材来源，也不代表商业发行授权。

`engine.mjs` 使用共享引擎的独立实例。每个实例闭包持有自己的目录，避免全局修改经典人物。内部存档使用单独的 key 和 theme 版本校验；不能混入公开三国逐鹿的旧存档。

### 需要明确的映射调整

- 周→蜀、商→魏、阐→吴、截→群是**技能阵营适配**，不只是显示文字。伐纣请周势力提供杀，王卫请商势力提供闪，护道由其他阐教仙桃救援时多恢复一点。
