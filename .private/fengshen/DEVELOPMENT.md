# 众神斗法开发与 UI 验收规范（必读）

修改或新增角色、卡牌、美术、布局、动画之前先读本文件。新卡不是“规则能运行、图片能加载”就完成：必须与现有卡面一致，由开发者完成检查，不把逐张找字体、裁切、按钮的问题交给用户。

开发、测试和发布收尾同时遵守 [全仓库清理规范](../DEVELOPMENT.md)：谁截图谁删，检查后清理不用的截图、测试产物及缓存；同一项目发布包与回滚备份合计最多保留最近 3 份。成功、失败、中断都要关闭本次启动的浏览器及子进程、预览服务和调试连接；限制测试并发及重试，禁止无界叠开 Chrome。

## 1. 卡牌字体：禁止缺字后偷偷换字体

- 所有牌名（包括杀、闪、仙桃、琼浆、炎杀、雷杀、缚神索及装备）统一用内嵌 **Ma Shan Zheng**。禁止单独为一张牌换字体，也不能依赖 iOS/Android/macOS 恰好安装了楷体。
- 当前运行字体：`assets/fonts/msz-v2.woff2`；完整 OFL 授权在同目录 `OFL.txt`。`coverage.json` 是 FontTools 从生成后的实际字库读取的 cmap，并绑定字库 SHA-256，不是手填的“预计支持字符”。
- 新增、改名时检查**全部汉字**，不是只检查标题 CSS。`getComputedStyle().fontFamily`、`document.fonts.check()` 成功不能证明每个字没有回退；浏览器验收必须读取实际使用的字体和字形数量。
- 人物信息、说明、按钮继续使用完整中文系统 UI 字体，不能把有限书法子集套到所有动态正文、昵称、数字上。书法用途增加新文本时，也要补齐其字形。
- 2026-10-12 已确认的事故：旧字库缺“琼、浆、炎、闭、粮、守、獬、豸、缚”等字，导致新卡与旧卡字体不同。以后出现此类缺字必须阻断构建，不能让用户先检查再补。

补字操作（无需 API，无线上编译）：

```sh
# 官方完整字库来源：https://github.com/google/fonts/tree/main/ofl/mashanzheng
# 下载 MaShanZheng-Regular.ttf 到临时目录，保留 OFL 授权。
python3 scripts/update-fengshen-font.py /absolute/path/MaShanZheng-Regular.ttf --version v3
# 将 style.css 的 @font-face URL 更新为脚本输出的新版本文件。
# 不手填 coverage.json，不覆盖旧 URL 来赌 Safari 缓存失效。
npm run test:fengshen:ui
```

生成脚本需要 Python FontTools 与 Brotli。普通发布检查只依赖 Node，不需要生产服务器安装 Python。脚本保留旧字库已有字符，并覆盖当前全部牌名、人物名、称号、技能名；生成后再次读取输出 cmap 校验。提交新 WOFF2、coverage.json 和新 URL，再检查官网字库实际加载版本。

## 2. 卡面只有一套构图，不按场景重新画

- 唯一入口 `presentation.mjs:cardFace()`，逻辑画布 **100×144**，用 `scaleCards()` 等比例缩放。手牌、中央出牌、判定、移动动画、选牌、图鉴、详情都复用它。
- 牌名横排、居中、完整显示；字号按名称长度统一分档，不给新卡单独写 magic number，不让基本牌旧样式把“琼浆”等多字标题当单字“杀”放大。
- 当前卡面最终布局在 `mobile-table.css`：上部点数/花色，中间插画，底部牌名。修改时检查 `app.js` CSS 导入顺序，不能只改被后面覆盖的旧选择器。不要凭单条 CSS 推断最终画面。
- 红/黑花色、点数、牌名位置和留白保持一致；插画不能烘焙牌名，也不能用不同图的文字代替统一标题。图片使用等比裁切，禁止拉伸、发虚、主体被切掉。
- 已上场卡牌使用绘制的位图大图及缩略图，不退回旧 SVG 占位图。更新素材同时改图鉴/介绍/封面引用；改内容须更换 URL 版本或更新内容 SHA。

## 3. 手机布局与操作不能倒退

- 至少验收 932×430、812×375、568×320 横屏及 390×844 竖屏；检查刘海/手势安全区、旋转往返、虚拟横屏后的坐标。
- 牌桌利用可用高度；不靠缩小整个界面修按钮。牌名不能截断、溢出、换行；选中牌抬升要留空间，手牌多时滚动手牌区，不能带着整个 Safari 页面移动。
- 必须实际点牌、点目标和确认；卡牌详情不能依赖鼠标悬停。选牌提示不遮合法目标、人物、按钮；公共血量/手牌数量清楚且不泄漏暗牌。
- 卡包/选择弹层正文可以滚动，确认按钮须可见、容易点，不被长说明挤出屏幕。游戏内提示用玩家理解的效果和触发时机，不展示实现术语。
- 动画按队列完成：效果出现 → 目标变化/收牌 → 稍作停留 → 下一阶段。禁止状态刷新提前撤走还在演示的卡片，禁止同一公开事件反复重播。恢复存档不能重复发牌/获得牌动画。
- 判定结果直接标在原判定牌上，不另放副本。公开判定牌被技能获得时，从原位置收走并移除旧桌面记录；飞行过程中目标手牌占位但不重复显牌，到达后才显示。反复渲染/旋转不能让旧牌回桌或重新飞一遍；实体 ID 不同但同牌面不能被误删。
- 牌桌只保留**当前结算链**，不是整回合出牌历史。下一张主牌开始立即替换上一组牌；发动无中生有/群攻不能留下先前杀与闪。当前牌在引擎没有后续待处理窗口且所有飞牌/摸牌/收牌/伤害动画完成后，短暂停留并淡出。闪后若仍有弃两张牌强制命中、追加杀、改判、濒死救援或后续技能，必须保留；群攻等全部对象响应完才能清空。不得依据“刚出过闪”猜测已结束，不改规则和牌堆，不因重渲染/旋转又从 lastPlayed 复活旧牌；独立弃牌/阵亡亮牌保留其短暂展示。
- 自动清桌只更新牌桌 DOM，不重建整个页面或联机社交层；不能打断悬浮按钮拖动、按住录音、菜单或其他正在进行的触摸操作。补测双端联机的拖动、录音与下一局流程。
- 所有公开出牌/响应统一排队飞入桌面：从实际出牌者位置出发、落地后亮牌。用户确认的表现是**待响应/受影响人物黄色边框＋飞牌**，不要新增黄色虚线、额外护盾/攻击/得牌图标或大光晕。**原有群攻连线必须保留，2.5 秒后自动消失**；无懈/后续响应不能重启旧群攻连线。无懈前标当前受影响对象，实际打出后用出牌者原位飞牌说明来源；未公开出牌之前绝不高亮他人持无懈者，也不替玩家揭露忠反身份。群体牌逐个标当前对象，不把后一人的目标套给前一张无懈。单机和联机 AI 的后续动作都要留出演示时间，旋转、重复快照、重新渲染和恢复存档不得重播。
- 仙桃/救援牌只保留出牌者→牌桌这一段统一飞牌，不再额外从救援者或牌桌飞向被救者；被救者的回血光效、实际 +血数字和体力变化必须保留。普通回血、自救、救他人、转化仙桃和联机快照走相同表现，刷新/旋转不能重播或叠出第二张救援牌。
- 天雷劫/雷击、迷魂阵、闭粮阵：仅在引擎最终公开 `reveal.hit` 为真时，先展示原判定牌与标记，再在**被影响武将的原人物卡**上播放约一秒的落雷/左右牢门合拢上锁/交叉封粮动画，把人物插画当成受影响的人；禁止退回中央小房子、小图标或另复制一张人物牌。姓名、体力、手牌数保持可读，判定牌不遮挡。改判阶段、落空、有效花色不命中时不提前播放；动画结束再继续本地判定，连发排队，刷新/旋转/恢复存档不重播。牢门、封粮、雷击有同步音效，遵守音效开关与触摸解锁，切后台后不补播，音频失败不能卡住游戏；减少动态效果下使用静态人物覆盖提示。
- 焚天焰与缚神索同样直接作用于受影响人物：结构化公开火焰伤害落地后才燃烧（包括连环传导的实际受伤者），连环状态真正改变后才缠紧/松开锁链。初始出牌、火攻亮牌、弃牌失败、破法抵消、重铸、重复设置相同状态都不能冒充命中；同一批多个目标同时播放人物效果，共用一段火声/金属声，不叠加多份音量。保留原伤害数字和公开连环状态，播放队列阻止抢先推进，恢复存档或重复快照不重播。
- 全屏状态、退出按钮、返回大厅和页面滚动一致；退出不清存档。触摸开始后再解锁音频；不能仅看“音效开”文字就声称手机有声。
- 人物详情必须使用当前 `playerView` 展示体力/手牌张数、装备（含防具和±1坐骑）、判定阵法/正在判定、翻面/连环/濒死等公开状态；不能读取对手暗手牌或未揭晓身份。不能发动技能时说明真实条件，不能只跳到人物介绍；触发类技能按钮须接入合法触发窗口，不允许为了“按钮能点”绕过原规则。迷魂阵不受距离/防御马限制；不能选时区分免疫技能、已有阵法和自身目标限制。迷魂阵无合法目标时不得静默自动转换成杀。
- 人物详情以**技能说明优先**：实战状态放在人物图右侧，不在图和技能前插入整块状态长文。默认只显示体力/手牌、实际装备与阵法、异常状态；空装备/空判定不占位，“存活/正面/未连环/未公开身份”等常态不逐项罗列。装备和状态完整效果放进默认收起的“状态详情”，重渲染不能擅自收起用户展开的说明。横屏（含 568×320）满装备、三阵法时，初次打开仍应直接看到第一项技能正文；图鉴介绍保留原布局，不能靠把全部文字缩小来验收。

## 4. 完成与发布门槛

1. `npm run test:fengshen:ui`：字库覆盖/二进制哈希/运行 URL 检查，以及全部卡牌的实际字体、字形数、标题边界、手机视口检查；真实点选/目标与手牌-桌面构图比对。
2. 新规则或角色额外运行 `npm run test:fengshen`；涉及联机共享规则再运行联机测试，前后端一起更新。纯字体变更不重启房间服务。
3. 预览及正式打包都会自动执行缺字检查；缺字、过期 cmap、指向旧字体时构建必须失败。禁止跳过检查来发布。
4. 看实际截图，尤其新增卡与旧卡并排：同一套字形、字重、字号分档、色彩、位置、图片比例；不要只凭“测试绿了”报 UI 合格。
5. 发布当前完整工作区，保护其他已落地修改；发布后核对官网新入口、字体/美术资源 SHA 和关键操作。`git push` 不等于上线，构建通过不等于官网验收通过。
6. 明确报告证据层级：静态检查、规则测试、Chromium 手机模拟、官网浏览器、实体 iPhone 分开写。没有真机测试就不能声称 Safari 真机通过。

新增内容 PR/提交说明至少写：新增名称及缺字检查结果、卡面共用入口、横竖屏截图/操作结果、线上资源版本、尚未验证的真机边界。不要再要求用户每次替开发者逐张复核。
