# 众神斗法 · 单机与好友联机

开发必读：[开发与 UI 验收规范](DEVELOPMENT.md)。新增卡牌必须通过内嵌字体缺字检查与手机卡面验收；`npm run test:fengshen:ui`，正式打包自动阻断缺字。不要把新增卡的字体、裁切、按钮问题留给用户检查。

## 好友联机（2026-10-11）

AI 反制群体回血按当前受益者逐个判断：目标满血／已阵亡时不会消耗破法，也不会反破法恢复无收益的回血；受伤目标仍按敌友关系及当前反制链判断。这个策略同时用于单机与联机服务端；只发布静态网页不会更新线上 AI。联机更新须先确认没有活跃房间；空闲部署脚本必须显式指定 `ONLINE_ARCHIVE` 为本次上传的包，避免误装旧包。

- 游戏首页「好友联机」进入现有 [联机大厅](https://vectorac.com/blogs/other/gamehall.html?game=fengshen)，不是第二套房间系统。创建众神斗法房可选 5／8 人身份局、1v1、2v2、3v3；默认思考 60 秒。邀请地址为 `https://vectorac.com/games/fengshen/?room=六位房号`。
- 新访客打开邀请链接只读取房间信息，必须点击「加入房间」才创建玩家并连接；预览／刷新／返回不会占位、退出旧房或初始化语音权限。重复点击加入只发一次入座请求；已有本房间凭据的玩家刷新直接恢复原座位。分享预览可能执行页面脚本，不能再把页面加载当作入座意图。
- 2v2 等待室显示 1、3 号同队／2、4 号同队；3v3 显示 1、3、5 号同队／2、4、6 号同队。空位、AI、真人都有队伍颜色，换座立即更新相对队友标记；身份局不展示队伍。
- 房主开始时自动用 AI 补空位，也可先加／移除 AI。身份在服务端随机分配，主公先选将，其余独立候选并行选择；对抗局同时选将后掷骰。整个引擎只有一份，出牌与响应由服务端队列裁决。
- 每位玩家的画面始终以自己为 0 号席：视图先隐藏他人手牌、身份、私有技能牌，再旋转公开座位；发出的目标再还原为服务端绝对席位。不能用浏览器自己运行 AI 替其他真人行动。
- 交流复用可拖动悬浮按钮：8 条牌类预录快捷语音、5 种定向互动和「按住说话」录音。短语／互动不需要麦克风，录音需要授权，内容只转发给同房其他玩家、不落盘；不调用在线 TTS。发送限流、白名单和同房鉴权在服务器执行。
- 断网不等于退出，现有 `resumeToken` 自动回原席；超时由 AI 接管，菜单中可取消托管。退出房间才放弃该席位，由 AI 继续。联机快照不覆盖单机存档。
- 联机终局默认保留牌桌，在操作区点「准备下一轮」／取消准备；全体在线真人准备后由原服务端自动开新一轮选将，保留房号与座位。「房间管理」仅切视图，不退出座位，可再回牌桌。服务端终态 FINISHED 的房间不能继续开局，按钮不会假装成功。
- 结算刷新恢复只使用当前标签页 sessionStorage 中已收到的本人视图，按房间／玩家隔离并核对局号、座位；新一轮或明确退出即删除，不覆盖单机存档。没有结算缓存的新标签页／新设备重连仍先显示房间，可正常准备。真人准备状态始终取服务端快照，缓存不参与准备或出牌裁决。
- 共享房间服务的房间仍在内存中：浏览器刷新／临时断网可恢复，**服务进程重启不能恢复旧房间**。升级先检查 `/api/rooms`，无人开房再重启；已有房间时要先征求玩家同意。
- 前端静态站与 `mahjong-service` 必须一起升级。服务端打包时把 `site/.vuepress/components/fengshen` 的规则／选将／投影编译进独立 JS，不将文档、QA 或美术打进服务，也不在 2C2G 线上机器编译依赖。

验证命令：`npm run test:fengshen`（规则／单机）、`npm run test:fengshen:online`（真实本机 WebSocket）、`npm run test:fengshen:online:browser`（两份隔离 Chromium）。Chromium 手机模拟不是实际 iPhone Safari 验收；最终以真机横竖屏、前后台切换和两部设备对局为准。

## 手机选择操作与身份猜测（2026-10-11）

- 七十二变／仙山采宝先点选并高亮，再点面板底部确认；重复点同一选项也可快速执行。选择绑定提示编号与状态版本，不能串到下一次操作。
- 偷牌、弃置牌、变身、采宝、推演统一预算安全区和短横屏高度：正文独立滚动，确认行不随正文滚走。改判仍在手牌区选牌，保留“确认改判／不改判”。
- 青色标识当前回合，紫色标识当前取宝人／改判者，金色标识选择。采宝的破法窗口不展示选牌大面板，保留人物与黄线；真正取走后，公开牌飞向接收者。
- 点击未揭晓角色右上角“？”可循环标记忠臣、反贼、内奸、清除。“猜”表示本地笔记，不是真实身份。笔记作为存档旁的数据保存，不输入引擎或 AI；揭晓后删除笔记，显示真实身份。旧裸游戏存档仍兼容。
- 验收边界：本轮浏览器连接连续超时。新增状态／合法动作／响应式高度预算测试与构建可复验，但不能替代 iPhone 横屏实际点击、裁切及动画验收。

## 单机玩法与操作

### 血量与手牌可读性（2026-10-11）

对手人物底部固定显示「血量 当前／上限」与「手牌 张数」，使用至少14px数字、高对比底色及血条；1点及以下标红，半血及以下标黄。手牌张数来自公开视图的 handCount，不从已隐藏的牌面数组推算，不暴露他人的牌。自己的同款指标放在手牌标题栏，不与人物技能／法宝重叠。装备保持叠在人物内部，为指标栏预留空间；联机昵称不盖住指标，摸牌动画落到手牌计数。

复验：`npm run test:fengshen:resources:browser`。覆盖五人／八人局、满装备、虚拟横屏与真正竖屏，以及三位手牌数字和合法目标点击；Chromium 模拟不能替代真机 Safari 验收。

### 手机牌桌修复（2026-10-10）

大量手牌不压缩到不可读：按真正的手牌滚动区高度计算牌面，横竖屏都预留选中抬升与角标空间。支持1～108张手牌的布局预算；实际浏览器覆盖60手牌与苦肉30→32→34的连续摸牌。定位选中牌按完整牌面宽度，而不是重叠的窄点击区域；新获得的手牌滚到可见区域，不移动整个文档。

小游戏列表封面沿用Kimi等已完成的原图，不重新替换素材。图片URL附带内容SHA版本；官网图片当前允许30天缓存，固定同一URL会让部分客户端继续使用旧封面。postbuild检查封面版本与文件内容一致，禁止改图后忘记更新引用。更新不需要清除Safari网站数据，也不删除游戏存档。

八人横屏使用五人紧凑顶排＋左右各一位，人物直接贴顶；不是按百分比把所有人物塞进扣掉手牌区的上半屏。横向内容统一避开iPhone刘海与圆角安全区，背景及人物视觉可上下贴边；操作按钮避开底部手势条。装备叠在人物内，不增加人物高度。自己的倒计时在手牌标题行，不覆盖头像。

单目标牌（杀、摄宝、破阵等）未确认时点另一名合法角色直接替换；选择对象阶段，人物与其装备区域只响应目标选择，无效对象不弹说明。借宝诛敌保留“武器持有者→被杀者”的顺序（可指向自己），多目标技能保留独立操作。未选手牌／技能时仍可查看人物、装备说明。

五谷使用独立居中浮层，完整等比例牌面单排横向滑动，不限制在普通出牌窄带中。普通出牌卡片依据中央剩余高度计算，利用手牌抬升预留空隙而不缩放整桌人物。装备使用插画小牌、槽位图标和距离角标，姓名采用完整系统中文字体，避免书法子集缺字而逐字回退。

### 干净牌桌交互（2026-10-11）

普通出牌与响应从实际出牌者位置飞入牌桌；无懈可击同样走飞牌动画，落地后才接下一段动作。群体牌保留原有全体连线，2.5秒后自动消失；后续无懈/响应不得重启这组线。当前响应／受影响人物用黄色外框提示，不新增黄色虚线、护盾或得牌图标。未公开出牌前不向他人暴露持无懈者或隐藏身份。破法取消独立选牌弹层，每个新响应窗口自动抬起一张合法破法手牌，在手牌操作区发动或不发动；再次破法恢复效果，不能把单个目标被抵消当作全体法术失效。按钮短时防连点，手牌不足或没有合法响应仍由引擎处理。单机等待动画完成，联机 AI 在公开出牌后留出演示时间；旋转、重复快照与重渲染不重播。

迷魂阵、天雷劫和技能判定直接在中央卡片翻牌、盖勾／叉，人物显示判定徽标，无全屏背景。石魄、悟道等获得公开判定牌时，使用公开的 judgment-keep 事件飞入手牌，不读取其他玩家的暗手牌。牌桌只保留当前结算链，下一张主牌立即替换旧组；引擎已无后续窗口且所有效果动画结束后，停留400ms再淡出180ms。闪后仍有强制命中/追加杀/救援等窗口时不清牌，群攻等所有人响应完才清；同一链最多12张展示牌，不保留整回合历史。展示副本不参与实体牌守恒或AI判断，不从旧lastPlayed复活清掉的牌，不重播获得牌动画。

本轮补了反制链、延时牌响应、公开判定归属、手牌隐私、连点保护与横竖屏尺寸测试；浏览器工具连接超时，尚未完成本轮实际浏览器动画／iPhone Safari视觉验收。

旋转、visualViewport变化、pageshow及后台回前台会重新测量。布局使用未缩放坐标，双指缩放由浏览器正常处理，不拦截gesture事件、也不反向抵消用户缩放。选牌只滚动手牌区，不使用scrollIntoView移动整个Safari视口。[可视视口缩放定义](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport/scale)。

默认横屏沿用斗地主机制：手机点击开始／继续后，竖屏持机时旋转整个游戏画面90度、交换逻辑宽高，并临时按虚拟视口评估本游戏媒体查询。不是强制锁定设备物理方向。用户实际旋转过手机后，本页允许自由横竖屏切换。目标线、移牌动画、推演拖动使用逆旋转坐标，不改变现在的牌桌布局。

Safari工具栏同样复用斗地主的滚动垫层方案：触屏进入游戏时解除文档滚动锁，加入物理innerHeight+120px垫层，游戏仍固定。可在牌桌空白处上滑，供Safari自身收起栏；收起后重测铺满。网页不能保证直接关闭浏览器原生UI；退出到大厅时移除垫层、恢复媒体查询，重复进入不重复添加。仍需实体iPhone验证实际工具栏行为。

推演有独立完整牌面区域与确认按钮，支持触摸／鼠标同排拖动排序、跨排拖动、横向溢出滑动；点击可换排，键盘左右排序／上下换排。拖动期间暂停思考计时，取消、旋转或后台中断不应出牌。最终确认仍由引擎校验全部卡牌ID，不改技能规则。

验收覆盖安全区模拟、932×430／844×390／667×375／568×320横屏、390×844／320×568竖屏与旋转往返；浏览器完成真实拖动与确认后的牌序验证，并做两倍缩放／冻结恢复模拟。没有实体iPhone长时间后台恢复的完成证据，发布后仍需要真机Safari复测。

身份局支持五人、八人：先随机身份，主公先选，再给其他角色发独立候选。其他身份在阵亡或终局公开，自己始终可以查看身份。

1v1／2v2／3v3 是本项目的简化队伍对抗，不冒称官方竞技模式：队伍公开、席位交替，全员先选将，之后掷骰定先手，按席位顺序轮转。没有身份主公加血、主公技或身份击杀奖惩。

手机支持横竖屏、叠牌及手牌横向滑动。判定中央翻牌后继续；推演牌序只对本人可见，改判使用手牌；转移攻击的范围按弃牌后装备计算；受伤分牌只能分配本次新得到的牌。没有响应资源时自动继续，有可用响应时允许选择。

正收益摸牌／收牌技能自动发动；裸衣、突袭、洛神等存在取舍的技能保留选择，分配牌与选择目标仍需操作。60秒超时进入AI托管，可随时接管。AI只接收玩家视图，不读取隐藏手牌、身份或牌堆。
